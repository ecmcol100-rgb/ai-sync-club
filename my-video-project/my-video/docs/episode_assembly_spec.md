# 부록 A. 조립 구현 기록 (2026-08-27 — 인수인계용)

조립은 `src/MokEpisode/`에 완료됨. 컴포지션 `MokEpisode`, 20,010프레임 = 667초 = 11:07 정확.

## A-1. timing.ts 실제 구조

모든 시각의 단일 원천. 조립부(index.tsx)에는 프레임 직접 기입이 0곳이다.

| 상수 | 내용 |
|---|---|
| `FPS`, `SEC(s)` | 30fps, 초→프레임 반올림 변환 |
| `SECTION_STARTS_SEC` / `SECTION_LENGTHS_SEC` | 섹션 s0~s6 시작·길이(초) — 본 사양서 1절 표 그대로 |
| `TOTAL_SEC` / `TOTAL_FRAMES` | 667 / 20010 — 파생값 |
| `S1_STAGES_SEC`, `S1_ITEM_INTERVAL_SEC` | 섹션1 5단계 시각, 예고 8개 간격(1.1초 — 마지막 항목 등장 후 0.33초 여유) |
| `S2` (객체) | intro/organPresent/organAnim/organEnd/bile/bileExpand/bileEnd/carnivore/food/bathing/bridge/end |
| `ORGAN_FREEZE_FRAME` (=25) | 2-a 정지 제시에 쓰는 컴포넌트 내부 프레임 — 등장 완료 직후·강조 점등 직전 |
| `S2B_STAGES_SEC`, `CARNIVORE_STAGES_SEC`, `FOOD_STAGES_SEC`, `S2C_STAGES_SEC` | 각 컴포넌트에 넘기는 단계 시각(컴포넌트 상대초) |
| `S3` / `S4` (객체) | 화면 전환 시각 — 본 사양서 2절 표 그대로 |
| `S3_CAPTIONS` / `S4_CAPTIONS` | 자막 구간. career는 알코올 문단을 비켜 career1/addiction/career2 세 구간 |
| `S4_D_POINTS_SEC` | 4-d 포인트 등장 — 3번째(술)가 알코올 문단 시작(패널 상대 24.5초)과 맞물림 |
| `TABLE_SKIP_FADE_FRAMES` (=15) | 대조표 내부 페이드인을 건너뛰는 오프셋 |
| `S5_STAGES_SEC` | 자가진단 5단계 |
| `YOUTUBE_CHAPTERS` | 섹션 상수에서 파생 — 지점 불일치가 구조적으로 불가능 |

모든 값이 0.1초 단위이므로 `SEC()` 반올림에서 인접 구간의 끝프레임 = 다음 시작프레임이 정확히 일치한다(1프레임 틈·겹침 없음). **값을 바꿀 때도 0.1초 단위를 유지할 것.**

## A-2. 임시 길이 배선과 오디오 교체 절차

현재 값은 5.5자/초 환산 임시 길이다. 오디오 확보 후:

1. 섹션별 오디오를 `public/audio/`에 배치
2. `calculateMetadata` + `getAudioDurationInSeconds`(@remotion/media-utils, 설치됨)로 실측 → `SECTION_LENGTHS_SEC` 교체, `SECTION_STARTS_SEC`는 누적합으로 재계산
3. 문단·자막·단계 시각(S1~S5 상수)을 섹션 길이의 글자 수 비율로 재분배 — 예외 둘:
   혈압 구간(5~8% 감속, 본 사양서 6절)과 `S4_I_STAGES_SEC[1]`(칩 벌어짐 —
   "목음체질이 아닙니다" 발화 시점을 파형에서 찾아 직접 지정, 6절 5항)
4. `<Audio>` 트랙을 index.tsx에 추가 (대조표 20초는 무음 공백 유지)
5. `YOUTUBE_CHAPTERS`는 자동 파생되므로 값만 확인
6. 전체 렌더 후 경계 검사 재실행 (아래 A-4 방법)

## A-3. 조립 과정에서 내린 판단과 이유

1. **2-a 3문단 배선** — 컴포넌트의 5.3초 타임라인은 2a 사양서상 수정 불가.
   ① 양 끝 제시(25.3초)는 `<Freeze frame={25}>` 정지, ② 이동부터는 **음수 오프셋
   중첩 Sequence**(`<Sequence from={-25}>`)로 같은 프레임에서 이어붙여 이음새 없음.
   애니 종료 후 최종 상태가 ③ 결론까지 자연 유지된다.
2. **대조표 진입** — "전환 없이 즉시 정지 화면"(4절)을 위해 내부 페이드인
   15프레임을 음수 오프셋으로 건너뜀.
3. **4-d 패널 연속** — 세 문단(전반/알코올/후반)에 패널 Sequence를 나누면
   포인트 애니메이션이 재시작되므로 패널은 하나로 연속시키고 자막만 교체.
   라벨(직업)도 하나로 유지.
4. **4-i 정답+예고 [가안]** — 전용 컴포넌트가 없어 EmphasisCaption 2연으로 배선.
   문안("가장 가까운 체질은 수음체질" / "목과 반대인 금 — 다음 편에서")은
   편 스펙 v5 28·30·31항에서 파생한 초안이었고, v6 47항으로 한 차례 확정 후
   v7 62~66항·v8 68~69항에서 재확정됨(이력은 전부 v9 문서에 수록).
   v7~v9 재확정분까지 2026-09-06 반영 완료 (A-5-2).

## A-6. 하단 레이아웃 재설계 (2026-09-05)

**목표**: 본문을 최대한 살리면서 내레이션 자막 60px 2줄을 넣는다. 단일 원천은
`src/EcmOverview/bottomLayout.ts`, 검수는 `BottomLayout` 컴포지션(눈금선 + DOM 실측 OK/NG).

### 실측

내레이션 60px × 행간 1.4 × 2줄 + 상하 여백 18 = **상자 204px**. 바닥 여백 78을 두면
**화면 하단 282px(y 798~1080)** 이 내레이션 몫이다. 이전 예약(하단 160px)보다 122px 더 필요.

### 어떻게 확보했나 — medical 띠를 예약 슬롯에서 뺐다

이전 스택은 항목 띠(56) + medical 띠(80) + disclaimer(48) + 간격 40 = 224px를
**상시 예약**했다. medical이 실제로 뜨는 시간은 667초 중 38초(혈압 문단)뿐이다.
그래서 medical을 혈압 화면의 본문 바로 아래(y 596~676)에 두고, 나머지 자막은
그대로 압축해 내려 쌓았다:

| 띠 | 이전 | 현재 | 변경 |
|---|---|---|---|
| 항목 행 (career/addiction 좌 · **출처 우**) | 686~742 (56) | 686~734 (48) | 높이 −8, 출처를 같은 행에 병치 |
| medical | 762~842 (80, 상시 예약) | **596~676 (80, 혈압 구간만)** | 크기·글자·테두리 불변, 위치만 |
| disclaimer | 862~910 (48) | 744~786 (42) | 높이 −6, 좌우 여백 26→22 |
| 띠 간격 | 20 | 10 / 12 | |
| 출처 | bottom 235, 31px, medical 구간 상향 330 | 항목 행 세로 중앙, 24px(크레딧 20) | 상향 이동(raisedRanges) 폐지 |

**CONTENT_MAX_Y는 686 그대로.** 조정할 필요가 없어졌다 — ItemPanel 3-d(667 종료)·대조표(653 종료)
등 17종 컴포넌트를 하나도 건드리지 않았다. 혈압 화면만 `MEDICAL_CONTENT_MAX_Y = 580`을

y 558에서 끝난다(실측). 항목 라벨(84~126)과의 간격 14.

### 판단 근거

- 안전 자막 사양서 §4의 필수 규칙(문구·타임코드 외부화, 시인성 순서, medical 비가림,
  career/addiction 배타, disclaimer 상시)은 모두 유지된다. §5의 "두 자리를 비워두는 방식"은
  권고였고, 그 취지(자막이 뜨고 질 때 다른 자막이 움직이지 않음)는 새 배치에서도 성립한다 —
  medical이 떠도 항목 행·disclaimer·출처는 1px도 움직이지 않는다.
- medical이 본문 카드 바로 아래에 서면서 혈압 사양서의 "이 화면에서 강조될 것은 ④뿐"이라는
  구도가 오히려 선명해졌다.
- 출처를 항목 행 우측에 두면 career 상자(좌, ~560px)와 같은 행을 쓴다. 한 줄 폭 상한을
  1300→1000으로 낮춰 두 요소가 만날 수 없게 했다 (1920 − 120 − 560 − 40 − 120 = 1080 > 1000).

### ItemPanel 본문 블록 상향 (같은 날, 후속)

3-d에서 note(y ~667)와 career 캡션(686~)이 19px밖에 안 떨어져 붙어 보였다.
캡션은 이미 슬롯(686~734) 안에 있었으므로 본문 쪽을 올렸다:

- 포인트 블록 아래 한계 `PANEL_BOTTOM = CONTENT_MAX_Y − 32 = 654` (이전 678)
- headline 없는 화면의 블록 시작 170 → **150** (항목 라벨 84~126 아래 24px)
- headline `lineHeight: 1.2` 명시 — 기본 행간(≈1.45)이면 headline이 309까지 내려와
  포인트 블록(300~)과 맞닿았다. 이제 문서대로 150~285에서 끝난다
- 명시한 sizeTier로 블록이 띠를 넘치면 콘솔 경고 (`[ItemPanel] … 띠를 넘습니다`)

결과: 3-d note 하단 ~648 → 캡션과 38px. 가장 빡빡한 3-d(추정 496.5 / 띠 504)·
4-f(493 / 504)·4-e(351 / 354)가 모두 들어간다. 10화면 sizeTier는 변경 없음.

### 개괄영상 보존

SourceCaptions·Subtitles는 개괄영상 씬(Section01~06, v5 확정 렌더)도 쓴다.
`BottomLayoutContext`로 프로파일을 분리해 EcmOverview/index.tsx가 `LEGACY_LAYOUT`
(내레이션 40px·bottom 56, 출처 31px·bottom 235)을 주입한다. 씬 파일은 손대지 않았다.
