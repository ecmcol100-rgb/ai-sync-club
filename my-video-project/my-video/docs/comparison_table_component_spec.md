# ComparisonTable — 9항목 대조표 컴포넌트 사양서

**용도**: 두 체질을 한 화면에서 대조하는 요약 표
**첫 적용**: 기본 시리즈 ① 목양·목음편 (섹션 4-h)
**재사용**: 전 시리즈 공통. **항목 데이터와 체질 정보만 편별로 주입**

---

## 1. 이 화면의 성격 — 다른 컴포넌트와 다릅니다

이 화면은 **20초간 정지 상태로 노출되며 내레이션이 없습니다.**

- 시청자가 **스크린샷으로 저장**하는 지점입니다
- **썸네일 후보 1순위**입니다
- 앞선 4분 44초 분량의 정보를 한 화면으로 압축하는 자리입니다

따라서 다른 컴포넌트와 우선순위가 다릅니다. **애니메이션보다 가독성과 정보 밀도가 우선**입니다. 화려한 등장 연출을 넣지 마십시오 — 저장하려는 사람에게는 방해가 됩니다.

**설계 기준**: 모바일에서 세로로 보든, PC에서 일시정지하든 **9행이 한눈에 읽혀야 합니다.**

---

## 2. 컴포넌트 인터페이스

```ts
type ComparisonRow = {
  label: string;       // '장기강약'
  left: string;        // 체질 A 내용
  right: string;       // 체질 B 내용
  shared?: boolean;    // true면 좌우 병합 셀로 렌더 (음식 항목)
};

type Props = {
  leftTitle: string;      // '목양체질'
  leftSub: string;        // '木陽 · Hepatonia'
  rightTitle: string;     // '목음체질'
  rightSub: string;       // '木陰 · Cholecystonia'
  rows: ComparisonRow[];  // 9행
  source: string;         // 출처 자막 문구
};
```

**`shared`가 이 컴포넌트의 핵심 기능입니다.** 음식 항목은 두 체질이 동일하므로 좌우를 나누지 않고 하나의 병합 셀로 그립니다. 지금 스펙 표에는 오른쪽에 "← 동일"로 적혀 있는데, 화면에서는 **병합 셀이 훨씬 명확합니다.** 두 체질의 공통점이 시각적으로 드러나는 것이 이 편의 메시지("양 끝은 같고 가운데가 다르다")와도 맞습니다.

### 좌표 제약

- 표 전체가 **y < 686**(`CONTENT_MAX_Y`) 안에서 끝나야 합니다
- 9행 + 헤더를 좁은 세로 공간에 넣어야 하므로, **이 컴포넌트가 좌표 제약을 가장 크게 받습니다**
- 들어가지 않으면 글자를 줄이기 전에 **행 높이와 여백을 먼저 조정**하십시오. 가독성이 최우선입니다
- 하단에는 disclaimer 자막이 상시 떠 있습니다

### 색 처리

- 좌우 열을 **체질 시그니처 컬러로 구분**합니다 (`CONSTITUTION_ACCENTS` 참조 — 목양 `#7F9E5E`, 목음 `#6FB3A8`)
- 색은 **헤더와 테두리에만** 쓰고 본문 텍스트는 가독성 우선으로 처리하십시오
- `shared` 행은 두 색의 중간이거나 중립색으로. 어느 한쪽에 속하지 않는다는 것이 보여야 합니다
- 항목 라벨 열은 중립색

## 5. 반드시 지켜야 할 규칙

- **화려한 등장 연출 금지.** 전체 페이드인 정도로 충분합니다. 행마다 순차 등장시키지 마십시오 — 20초 정지 화면이고 스크린샷 대상입니다
- **9행을 줄이거나 합치지 마십시오.** 9항목 체계가 이 시리즈의 구조입니다
- **`shared` 행을 좌우로 나누지 마십시오.** 병합 셀이어야 공통이라는 것이 드러납니다
- **"최강/최약" 문구를 쓰지 마십시오.** 장기강약 행은 "선두 / 약한 자리" 표현을 그대로 씁니다
- 표 전체가 y < 686 안에서 끝나야 합니다
- 색·폰트는 공통 스타일 재사용. 새로 정의하지 마십시오
- **1080p에서 각 셀의 글자가 잘리거나 넘치지 않아야 합니다.** 줄바꿈(`\n`)을 지원하십시오

## 6. 검수 항목

- [ ] 9행이 모두 보이는가
- [ ] 표 전체가 y < 686 안에서 끝나는가
- [ ] 음식 행이 좌우 병합 셀로 그려지는가
- [ ] 좌우 열이 체질 색으로 구분되는가
- [ ] 본문 텍스트 가독성이 확보되는가 — 색 대비, 글자 크기
- [ ] 셀 내용이 잘리거나 넘치지 않는가
- [ ] 줄바꿈이 의도대로 적용되는가
- [ ] 출처 자막이 있는가
- [ ] disclaimer 자막과 겹치지 않는가
- [ ] 등장 연출이 과하지 않은가
- [ ] **일시정지 상태에서 스크린샷으로 저장했을 때 그 자체로 완결된 정보가 되는가** — 최종 판단 기준
- [ ] **썸네일로 잘라 썼을 때 읽히는 부분이 있는가** — 상단 헤더 영역만으로도 무엇에 관한 표인지 전달되어야 함

## 7. 썸네일 활용 메모

이 화면은 썸네일 후보입니다. 다만 **9행 전체를 썸네일에 넣으면 아무것도 읽히지 않습니다.**

썸네일용으로는 이 컴포넌트를 그대로 쓰지 말고, **상단 헤더(두 체질명) + 대비가 가장 선명한 2~3행만 확대**한 별도 구성을 권합니다. 그 작업은 이 컴포넌트와 분리해 나중에 진행하십시오.

이 사양서의 범위는 **본편 4-h 화면**입니다.
